# RiotFix

[![CI](https://github.com/IskhakovMA/riotfix/actions/workflows/ci.yml/badge.svg)](https://github.com/IskhakovMA/riotfix/actions/workflows/ci.yml)
[![Release](https://img.shields.io/github/v/release/IskhakovMA/riotfix?include_prereleases&label=release)](https://github.com/IskhakovMA/riotfix/releases)
[![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)

Бесплатная утилита для Windows 10/11, которая проверяет подключение к сервисам Riot Games
(Riot Client, VALORANT, League of Legends) и, если находит сетевую проблему, предлагает
проверенное исправление через файл `hosts`.

**[⬇ Скачать последнюю версию](https://github.com/IskhakovMA/riotfix/releases)**

> RiotFix — независимый проект с открытым исходным кодом. Он не связан с Riot Games и не одобрен ею.
> Версии 0.x — предварительные: программа ещё не проверена на большом числе компьютеров с реальной проблемой.

### Что нового в 0.2.1

- **Одна кнопка — понятный результат.** На главном экране только состояние («Подключение работает»,
  «Обнаружена проблема с подключением», «Не удалось найти безопасное исправление», «Изменения применены»),
  одна короткая фраза и одна главная кнопка: «Проверить подключение» или «Исправить подключение».
  «Отменить изменения» появляется небольшой ссылкой, только если RiotFix что-то менял. Адреса, названия
  серверов и технические статусы на главный экран не выводятся.
- **Подробности — по кнопке ⓘ** в правом верхнем углу: полный технический отчёт, копирование отчёта для
  поддержки, папка журналов и путь к файлу `hosts`. Диагностика внутри программы не упрощалась.
- **Кратковременный сбой DNS больше не приводит к лишним записям.** Если системный DNS не ответил, RiotFix
  очищает DNS-кэш Windows и повторяет запрос через 2 и ещё через 3 секунды; исправление предлагается, только если
  сбой не прошёл. Исправление, найденное из-за сбоя DNS, перед запросом прав администратора всегда
  перепроверяется с нуля.

### Что нового в 0.2.0

- **Точнее оценивается состояние сервиса с несколькими адресами.** Учитываются все адреса, а не только первый
  в ответе DNS (порядок адресов меняется от запроса к запросу). Адрес, который отвечает мгновенным отказом,
  клиент сразу пропускает — такая ситуация больше не считается неисправностью и не приводит к правке `hosts`.
- **Основные и вспомогательные сервисы.** Недоступность только `account.riotgames.com` и `data.riotgames.com`
  больше не показывается как критическая ошибка (подробнее — в разделе 4).
- **Повторная проверка перед исправлением.** Перед запросом прав администратора RiotFix заново проверяет
  найденные адреса и файл `hosts`; устаревший результат перепроверяется целиком (раздел 5).
- **Проверка обновлений** через GitHub Releases — не чаще раза в сутки, без скачивания и запуска файлов (раздел 8).
- Результат после исправления описывается осторожнее; автоматического отката нет — только ручной.

## 1. Что такое RiotFix

Небольшая программа с одной кнопкой. Она:

1. проверяет, отвечают ли сервисы Riot, к которым подключается Riot Client;
2. если какой-то сервис недоступен — ищет для него рабочий адрес и **дважды проверяет** его;
3. после вашего согласия добавляет найденные адреса в файл `hosts` и повторяет проверку;
4. честно показывает результат: что именно заработало, а что нет.

Программа не требует регистрации, не собирает данные, не отправляет телеметрию и не работает в фоне.

## 2. Какие проблемы он может решить

RiotFix помогает, когда проблема в том, **к какому адресу** компьютер подключается:

- системный DNS (обычно DNS провайдера) возвращает для сервисов Riot неработающий или подменённый адрес;
- часть серверов Riot недоступна из вашей сети, а другие адреса из официальных DNS-ответов работают;
- в `hosts` осталась старая ручная правка с устаревшими IP-адресами.

Проверяются сервисы, с которыми чаще всего возникают проблемы:
`auth.riotgames.com`, `account.riotgames.com`, `clientconfig.rpg.riotgames.com`,
`entitlements.auth.riotgames.com`, `data.riotgames.com`, `sieve.services.riotcdn.net`.

RiotFix **не поможет**, если:

- соединение блокируется по имени сайта (DPI/SNI-фильтрация) — тогда смена адреса ничего не меняет, и программа это увидит;
- проблема в аккаунте, его блокировке, регионе, Riot Vanguard или игровых серверах;
- Riot Client подключается через прокси или VPN;
- сервисы Riot недоступны из-за сбоя на стороне самой Riot Games.

## 3. Как скачать и запустить

1. Откройте страницу [Releases](https://github.com/IskhakovMA/riotfix/releases) и скачайте `RiotFix.exe`.
2. Запустите файл. Устанавливать .NET или что-то ещё не нужно (нужна 64-битная Windows 10 или 11).
3. Нажмите **«Проверить подключение»**.
4. Если найдено исправление, нажмите **«Исправить»** и подтвердите запрос Windows на права администратора.
5. Перезапустите Riot Client.

**Предупреждение SmartScreen.** Файл не подписан платным сертификатом, поэтому Windows может показать окно
«Windows защитила ваш компьютер». Нажмите «Подробнее» → «Выполнить в любом случае».
Если сомневаетесь — проверьте контрольную сумму (она опубликована рядом с файлом в каждом релизе):

```powershell
Get-FileHash .\RiotFix.exe -Algorithm SHA256
```

Значение должно совпасть с содержимым файла `RiotFix.exe.sha256`.

## 4. Как работает автоматическая диагностика

Для каждого сервиса RiotFix выполняет ту же цепочку, что и Riot Client:

| Шаг | Что проверяется |
| --- | --- |
| DNS | В какой адрес Windows превращает имя сервиса (с учётом файла `hosts`) |
| TCP | Открывается ли соединение с портом 443 |
| TLS | Устанавливается ли защищённое соединение с правильным именем сервера (SNI), действителен ли сертификат и выдан ли он именно для этого имени |
| HTTPS | Отвечает ли сервер на обычный запрос `GET /` |

Ответы `401`, `403`, `404`, `405` и перенаправления означают, что сервер доступен по сети: это не ошибка
подключения, но и не доказательство того, что вход в игру заработает. Ответы `5xx` — ошибка на стороне сервера;
`hosts` здесь не поможет.

**Несколько адресов у одного сервиса.** Проверяются до 4 адресов IPv4 и 2 адресов IPv6 из ответа DNS:

| Что получилось | Как RiotFix это оценивает |
| --- | --- |
| Все адреса работают | «Доступен» |
| Часть адресов отвечает мгновенным отказом (соединение отклонено или сброшено, нет маршрута IPv6), остальные работают | «Доступен (не все адреса)». Клиент сразу переходит к следующему адресу, исправление не нужно |
| Часть адресов зависает (таймаут TCP) или обрывается на TLS/HTTPS, остальные работают | «Работает нестабильно». Клиент периодически попадает на плохой адрес; предлагается закрепить проверенный рабочий |
| DNS вернул непубличный адрес (например, `10.x.x.x` или `127.0.0.1`) рядом с рабочим | «Работает нестабильно» — это частый признак подмены ответа DNS. К такому адресу RiotFix не подключается |
| Не работает ни один адрес | «Недоступен» |

**Почему недоступный отдельный сервис не всегда мешает входу.** RiotFix проверяет сетевую доступность
нескольких адресов Riot, а не работу Riot Client целиком. Сервисы делятся на две группы:

- основные — вход (`auth`), настройки клиента (`clientconfig`), доступ к играм (`entitlements`), служебный сервис `sieve`;
- вспомогательные — сайт учётной записи (`account`) и служба данных (`data`).

На реальном ПК с проблемами подключения (октябрь 2026) после исправления `account` и `data` по-прежнему
не отвечали (таймаут TLS), а вход в Riot Client и матч в VALORANT работали. Поэтому, если отвечают все
основные сервисы, RiotFix сообщает об ограничениях, но не называет их критической ошибкой. Обратное тоже
верно: недоступность основного сервиса в проверке не доказывает, что вход невозможен, — проверка не
воспроизводит авторизацию и не заглядывает внутрь клиента.

Если сервис недоступен, RiotFix ищет альтернативный адрес:

1. Запрашивает адреса этого сервиса у доверенных DNS-серверов по защищённому протоколу DNS-over-HTTPS
   (Cloudflare, Google Public DNS, Quad9, AdGuard без фильтрации). Подменить такой ответ по пути нельзя.
2. Отбрасывает непубличные адреса (локальные, служебные и т. п.).
3. Проверяет не больше 6 адресов на сервис — никакого перебора.
4. Принимает адрес, только если он **два раза подряд** прошёл всю цепочку TCP → TLS → HTTPS
   с действительным сертификатом для нужного имени.
5. Из подходящих выбирает IPv4-адрес, который назвало больше DNS-серверов и который быстрее отвечает.

Если ни один адрес не прошёл проверку, файл `hosts` **не изменяется**.

**Если системный DNS не ответил.** Такие сбои часто длятся несколько секунд (в реальном журнале DNS не ответил
сразу для всех шести сервисов, а через несколько секунд всё снова работало). Поэтому перед поиском альтернатив
RiotFix один раз очищает DNS-кэш Windows и повторяет запрос через 2 и ещё через 3 секунды. Если DNS так и не
ответил, проблема считается устойчивой и исправление предлагается как обычно.
Проверка сертификатов никогда не отключается.

Готовые IP-адреса из интернета (например, из инструкций на форумах) RiotFix не использует.

**Почему источников адресов не стало больше.** Сервисы Riot работают через Cloudflare, и все публичные
DNS-серверы возвращают для них один и тот же набор адресов. Если эти адреса не отвечают, других адресов,
обоснованно привязанных именно к этому домену, нет. Подбирать «соседние» адреса из сетей Cloudflare было бы
перебором без доказательств, поэтому RiotFix так не делает и честно сообщает, что исправления нет.

## 5. Какие изменения вносит программа

RiotFix изменяет только файл `C:\Windows\System32\drivers\etc\hosts` и только после вашего подтверждения.
В конец файла добавляется собственный блок:

```text
# >>> RiotFix BEGIN (managed block, https://github.com/IskhakovMA/riotfix)
104.16.120.50 auth.riotgames.com # riotfix:1a2b3c4d
# <<< RiotFix END
```

- Метка `# riotfix:…` содержит контрольную сумму строки. Если вы отредактируете строку вручную,
  RiotFix перестанет считать её своей и не удалит.
- Все остальные строки, комментарии, кодировка и переводы строк сохраняются байт в байт.
- Повторное исправление обновляет блок, а не дублирует записи.
- Если в `hosts` уже есть **чужая** запись для сервиса Riot, RiotFix покажет её и закомментирует только с вашего
  согласия (вернуть её можно кнопкой «Отменить изменения»). Строку, которая затрагивает и другие сайты,
  программа не трогает никогда.
- Перед первым изменением создаётся резервная копия `hosts.riotfix-original.bak` рядом с файлом `hosts`,
  перед каждым следующим — `hosts.riotfix-previous.bak`.
- Запись выполняется через временный файл и атомарную замену; права доступа к файлу сохраняются.
- После записи RiotFix очищает DNS-кэш Windows и автоматически повторяет проверку.

Права администратора запрашиваются через стандартное окно UAC только на момент записи —
сама программа работает с обычными правами.

**Повторная проверка перед записью.** Между проверкой и нажатием «Исправить» может пройти много времени.
Поэтому перед окном подтверждения и ещё раз непосредственно перед запросом UAC RiotFix:

1. перепроверяет каждый новый адрес полной цепочкой TCP → TLS (SNI, сертификат) → HTTPS;
2. убеждается, что файл `hosts` не изменился с момента проверки;
3. если результат старше 5 минут, файл изменился или адрес перестал отвечать — запускает проверку заново.

Если новая проверка нашла другие адреса, RiotFix показывает их и просит нажать «Исправить» ещё раз.
Если исправление больше не нужно или подтвердить его нельзя, права администратора не запрашиваются
и `hosts` не меняется. После записи проверка выполняется ещё раз; автоматического отката по её итогам нет.

## 6. Как отменить изменения

**Кнопкой.** Нажмите «Отменить изменения» — RiotFix удалит только свои строки и вернёт закомментированные
чужие записи. Изменения, которые вы сделали в `hosts` сами, останутся.

Как RiotFix понимает, какие строки его: каждая его строка содержит контрольную сумму своего содержимого.
Строки, которые вы изменили вручную, перестают ей соответствовать — их RiotFix не трогает. Файл без перевода
строки в конце после отката возвращается байт в байт. Записи, сделанные версией 0.1.0, распознаются и
откатываются так же. Сам RiotFix ничего не откатывает автоматически: если после исправления часть сервисов
не отвечает, но Riot Client работает, делать ничего не нужно.

**Вручную.** Откройте Блокнот от имени администратора, откройте файл
`C:\Windows\System32\drivers\etc\hosts` и удалите строки от `# >>> RiotFix BEGIN` до `# <<< RiotFix END`.
Строки вида `# riotfix-off:… ` — это закомментированные RiotFix записи: уберите начало строки до
исходного текста, чтобы вернуть их.

**Из резервной копии.** Файл `hosts.riotfix-original.bak` в той же папке — состояние до первого изменения.

## 7. Ограничения и возможные ошибки

- Проверяется сетевая доступность (DNS, TCP, TLS, HTTPS). Успешная проверка **не гарантирует**,
  что вход в аккаунт и игра заработают: авторизация, игровые серверы и Vanguard не проверяются.
- Проверяются 6 сервисов из списка выше. Другие серверы Riot (игровые, чат, патчи) не проверяются.
- Найденный адрес может со временем перестать работать. Запустите проверку снова — RiotFix заменит
  устаревшую запись.
- Если в Windows настроен системный прокси, Riot Client может подключаться через него, и записи `hosts`
  не подействуют. Об этом сообщается в подробностях (кнопка ⓘ).
- Если файл `hosts` защищён антивирусом (например, «Контролируемый доступ к папкам»), помечен как
  «Только для чтения» или занят другой программой, RiotFix покажет понятную ошибку и ничего не изменит.
  Отключать защиту программа не пытается.
- Режим высокой контрастности Windows поддерживается частично (используется светлая тема).
- Версия 0.1.0 проверена на одном реальном ПК с проблемами подключения: после исправления вход в Riot Client
  и игра в VALORANT работали. Связь между правкой `hosts` и восстановлением доступа при этом строго не доказана,
  а одного случая недостаточно, чтобы говорить о надёжности. Версия 0.2.0 проверена автоматическими тестами
  и запуском на Windows в CI. Пожалуйста, сообщайте о результатах в
  [Issues](https://github.com/IskhakovMA/riotfix/issues) — приложите отчёт (кнопка ⓘ → «Скопировать отчёт»).
- Разделение на основные и вспомогательные сервисы основано на наблюдении, а не на документации Riot.

Журналы работы хранятся в `%LocalAppData%\RiotFix\logs` (последние 10 дней).

## 8. Безопасность

**Проверка обновлений.** При открытии окна RiotFix не чаще раза в 24 часа делает один анонимный запрос
к `api.github.com` (список релизов этого репозитория). Таймаут — 5 секунд, размер ответа ограничен,
ссылка принимается только на страницу релиза `github.com/IskhakovMA/riotfix`. Без интернета проверка молча
пропускается. Если есть новая версия, над результатом проверки появляется небольшое уведомление: «Скачать»
открывает страницу релиза в браузере, крестик скрывает уведомление для этой версии навсегда. RiotFix ничего
не скачивает и не запускает сам и не запрашивает для этого прав администратора. Пока RiotFix имеет версию 0.x,
предлагаются и предварительные версии. Время последней проверки хранится в `%LocalAppData%\RiotFix\update-state.json`.

- **Никаких учётных данных.** RiotFix не читает и не запрашивает логины, пароли, токены и cookie Riot.
  Проверочный запрос — анонимный `GET /` без каких-либо данных.
- **Нет телеметрии и серверов.** Программа обращается только к проверяемым сервисам Riot, к публичным
  DNS-over-HTTPS серверам и (не чаще раза в сутки) к GitHub Releases для проверки обновлений. Своего сервера у проекта нет.
- **Не трогает игру.** Нет вмешательства в Riot Vanguard, античит, процессы и файлы игр.
  Программа только проверяет по имени, запущен ли Riot Client, чтобы напомнить о перезапуске.
- **Минимум прав.** Окно программы работает без прав администратора. Для записи запускается отдельный короткий
  процесс через UAC, который принимает только имена из встроенного списка сервисов Riot и только публичные
  IP-адреса. Любые другие аргументы он отклоняет. Путь к `hosts` он берёт только из системного API и реестра HKLM
  (не из переменных окружения пользователя), загружает системные DLL только из System32 и отказывается писать
  через символические ссылки.
- **Журналы без персональных данных.** В журнал пишутся имена сервисов Riot, адреса серверов Riot и типы
  ошибок. Путь к профилю пользователя вырезается.
- **Открытый код и проверяемые сборки.** EXE собирается только в GitHub Actions из этого репозитория после
  успешных тестов; к каждому релизу прилагается SHA-256.

Нашли уязвимость? Напишите через [Security Advisories](https://github.com/IskhakovMA/riotfix/security/advisories/new),
не публикуя детали в открытых Issues.

## 9. Сборка из исходного кода

Нужен [.NET SDK 10](https://dotnet.microsoft.com/download/dotnet/10.0).

```powershell
git clone https://github.com/IskhakovMA/riotfix.git
cd riotfix
dotnet test RiotFix.slnx -c Release
dotnet publish src/RiotFix.App/RiotFix.App.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -o publish
```

Готовый файл: `publish\RiotFix.exe`.

Структура:

| Папка | Содержимое |
| --- | --- |
| `src/RiotFix.Core` | Диагностика (DNS, DNS-over-HTTPS, TCP/TLS/HTTPS), выбор адреса, работа с `hosts`, протокол UAC-помощника. Без зависимостей от Windows — тестируется на любой ОС. |
| `src/RiotFix.App` | Интерфейс на WPF, запуск через UAC, тема Windows. |
| `tests/RiotFix.Core.Tests` | Тесты xUnit с поддельными файловой системой и сетью (настоящий `hosts` не используется). |

Тесты не изменяют настоящий файл `hosts`: CI на Windows дополнительно сверяет его контрольную сумму до и после.
